# Problem Brief: Microsoft 365 Copilot Integration

## Business Problem

Microsoft wants customers to buy and use Microsoft 365 Copilot licences. EAI needs a credible way for those customers to access governed EAI knowledge and workflows from the Microsoft tools where they already work, without duplicating EAI security, tenant isolation, or AI orchestration.

## Target Outcome

Define a commercially clear integration offer and a safe reference architecture that answers:

- where the customer interacts with Copilot;
- which EAI capabilities Copilot may read or action;
- where identity, authorization, audit, and tenant boundaries are enforced;
- when EAI data remains in EAI, is retrieved live, or is indexed into Microsoft 365;
- which Microsoft licences and consumption charges apply.

## Root Cause

“Copilot integration” can mean several different products: an agent in Microsoft 365, a connector that makes EAI content discoverable, or Copilot APIs embedded in an EAI app. Treating these as one architecture would create unclear commercial packaging and unsafe trust boundaries.

## Initial Success Measure

Select one pilot journey, one customer tenant, and one distribution model with an approved identity and data boundary. The pilot must demonstrate user-scoped access, tenant isolation, auditable reads/actions, and a cost model that can be explained to the customer.
